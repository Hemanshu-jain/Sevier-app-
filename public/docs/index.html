Handoff API

Send your overdue loan accounts to Handoff from your own loan system, automatically, instead of uploading a spreadsheet every month. Each account becomes a recovery case that your finance team reviews, approves, and assigns to field agents in Handoff.

The API does the same job as Monthly register → Import monthly file, using the same fields and the same rules. Anything you can put in the Excel/CSV register, you can send through the API.

Authentication

Every request needs your API key. Create one in Handoff under Settings → API keys. Keys start with hk_ and are shown only once, so copy the key when it's created and store it safely.

Send the key in the Authorization header:

Authorization: Bearer hk_your_api_key_here
Keep the key secret. Treat it like a password. Use it only from your server, never in a mobile app or web page, and don't share it on chat or email. If a key leaks, revoke it in Settings → API keys and create a new one. Every key belongs to your company, so cases it uploads land in your workspace.

Base URL & format

https://handoff.bhodhix.com

Requests and responses are JSON. Send Content-Type: application/json with every request that has a body. All endpoints use HTTPS.

Upload cases

POST/api/v1/cases

Creates or updates recovery cases. Send up to 1,000 accounts in one request.

Matching is by accountNumber. If an open case already has that account number, it is updated with the new amount and overdue days; otherwise a new case is created. That means you can safely send your whole overdue list every day or month.

Request body

Send an array of cases, or an object with a cases array. A single case object also works. See Case fields for every field.

curl -X POST https://handoff.bhodhix.com/api/v1/cases \
  -H "Authorization: Bearer hk_your_api_key_here" \
  -H "Content-Type: application/json" \
  -d '{
    "cases": [
      {
        "accountNumber": "LN-2026-10045",
        "borrowerName": "Rohan Malhotra",
        "borrowerMobile": "9812345678",
        "borrowerAddress": "12 MG Road, Shivaji Nagar, Pune",
        "registration": "MH12 AB 4471",
        "makeModel": "Maruti Suzuki Swift VXi",
        "vehicleType": "4-wheeler",
        "chassis": "MA3EWDE1S00512345",
        "branch": "Pune Central",
        "pendingAmount": 148500,
        "overdueDays": 92
      }
    ]
  }'

Response — 201 Created

{
  "accepted": 1,        // rows saved (created + updated)
  "rejected": 0,        // rows skipped because of errors
  "created": 1,         // new cases
  "updated": 0,         // existing open cases refreshed
  "billing": {
    "paid": 1,                // rows paid from your wallet
    "pending": 0,             // rows waiting for a wallet recharge
    "amountPaidPaise": 1000,
    "amountDuePaise": 0
  },
  "errors": []
}

When some rows are invalid

Valid rows are still saved. Invalid rows are listed in errors, and index is the row's position in the array you sent (starting at 0). Fix those rows and send them again.

{
  "accepted": 9,
  "rejected": 1,
  "created": 7,
  "updated": 2,
  "billing": { "paid": 9, "pending": 0, "amountPaidPaise": 9000, "amountDuePaise": 0 },
  "errors": [
    { "index": 3, "message": "Check mobile, vehicle type." }
  ]
}

If no row is valid, you get 422 with the same errors list and nothing is saved.

List cases

GET/api/v1/cases?status=assigned&limit=100

Returns your cases, most recently updated first. Use it to follow each account's progress.

Query parameterDescription
status optionalOnly cases in this status. See Case statuses.
limit optionalHow many to return, 1–500. Default 100.
curl https://handoff.bhodhix.com/api/v1/cases?status=assigned \
  -H "Authorization: Bearer hk_your_api_key_here"

Response — 200 OK

{
  "cases": [
    {
      "id": "RC-2609-28465D",
      "accountNumber": "LN-2026-10045",
      "borrowerName": "Rohan Malhotra",
      "registration": "MH12 AB 4471",
      "status": "assigned",
      "billingLocked": false,
      "createdAt": "2026-09-26T06:10:00.000Z",
      "updatedAt": "2026-09-26T09:42:00.000Z"
    }
  ]
}

billingLocked: true means the case is waiting for a wallet recharge before your team can work on it.

Cancel a case

DELETE/api/v1/cases/{accountNumber}

Cancels the open case for this account number, for example when the customer pays before recovery starts. This only works while the case is still imported and no agent has it yet. After that, manage the case inside Handoff.

curl -X DELETE https://handoff.bhodhix.com/api/v1/cases/LN-2026-10045 \
  -H "Authorization: Bearer hk_your_api_key_here"

Response — 200 OK

{ "id": "RC-2609-28465D", "accountNumber": "LN-2026-10045", "status": "cancelled" }
Cancelling does not refund the upload charge. You get 404 if no open case uses that account number, and 409 if the case is already with an agent.

Case fields

These are the same columns as the monthly register spreadsheet.

FieldTypeDescription
accountNumber requiredstringYour loan account number. Handoff uses it to match and update cases, so keep it stable.
borrowerName requiredstringCustomer's full name.
borrowerMobile requiredstringIndian mobile number. 9812345678, +91 98123 45678 and 919812345678 are all accepted.
borrowerAddress requiredstringCustomer's address, which the agent uses for field visits.
registration requiredstringVehicle number, for example MH12 AB 4471. It is saved in capitals.
makeModel requiredstringMake and model, for example Honda Activa 6G.
vehicleType requiredstring2-wheeler or 4-wheeler. 2W/4W also work.
pendingAmount requirednumber or stringAmount due in rupees, up to 2 decimals. 148500, "148500.50" and "₹1,48,500" all work.
overdueDays requiredintegerDays overdue, a whole number such as 92.
chassis optionalstringChassis number. Agents use the last 6 characters to verify the vehicle.
branch optionalstringYour branch name, used for grouping and reports.

Case statuses

StatusMeaning
importedReceived, waiting for your team to approve recovery authority and assign an agent.
assignedWith one or more field agents.
unable_to_recoverThe agent could not recover the vehicle, with a reason. Your team can reassign it.
custody_reviewVehicle recovered and parked, waiting for your team to check the custody report.
payment_pendingCustody approved, waiting for the customer to clear dues.
payment_confirmedYour team confirmed payment. A release pass can be issued.
release_pass_printedRelease pass issued to the customer.
closedVehicle released. Done.
cancelledCancelled through the API or by your team.

Errors

Error responses have an error message you can show or log.

{ "error": "A valid API key is required." }
CodeMeaningWhat to do
401Missing, wrong, or revoked API key.Check the Authorization header, or create a new key.
404No open case with that account number (cancel only).Check the account number.
409The case is already with an agent (cancel only).Manage it inside Handoff.
422Invalid request. The body is empty, has more than 1,000 rows, or no row is valid.Read errors, fix the rows, and retry.
429Too many requests.Wait the number of seconds in the Retry-After header, then retry.
500Something went wrong on our side.Retry after a minute. If it keeps happening, contact us.

Limits & billing

LimitValue
Cases per request1 – 1,000
Requests per key120 per minute
Request size2 MB
Active API keys1 included. Request more in Settings → API keys.

Each accepted row is charged at your per-vehicle rate, the same as a spreadsheet import, from your Handoff wallet. The billing part of the upload response shows how many rows were paid now and how many are waiting. If your wallet runs short, rows are still saved but stay locked (billingLocked: true) until you recharge. They unlock automatically after that.

Best practice: send your full overdue list once a day. Matching by account number keeps it free of duplicates. To drop an account that no longer needs recovery, cancel it with DELETE.
